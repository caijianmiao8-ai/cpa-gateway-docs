CPA Gateway

OpenAI 兼容的统一网关。一把 vkey 调通 Codex / Gemini / Groq / OpenRouter 等多家上游,实时配额随响应返回。

配置 — 填一次,下方所有示例自动更新

概览

本服务是 cli-proxy-api 的前置网关:统一鉴权、按虚拟 key (vkey) 限速 / 限额 / 限模型,转发到多家上游 LLM 提供方。

  • 接口 OpenAI 兼容(也支持 Anthropic /v1/messages 原生格式)
  • 支持 SSE 流式(stream: true)
  • 每次响应都带 X-RateLimit-* / X-Budget-* header,客户端可实时算余额
  • CORS 全开(Access-Control-Allow-Origin: *),浏览器直连可用

鉴权

所有请求需带 Bearer token:

Authorization: Bearer $VKEY

或者用 X-API-Key: vk-...。两种都支持。无效 / 过期 / 被禁用的 vkey 返回 401。

Chat / Responses

POST /v1/chat/completions OpenAI 标准 chat,完全兼容

请求体跟 OpenAI 一致:model、messages[]、可选 stream、max_tokens、temperature、tools 等。

curl -sS __BASE_URL__/v1/chat/completions \
  -H "Authorization: Bearer $VKEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llama-3.3-70b",
    "messages": [
      {"role": "system", "content": "你是一个简明扼要的助手。"},
      {"role": "user",   "content": "用一句话解释 SSE。"}
    ]
  }'

流式

加 "stream": true,响应是 text/event-stream,每个 chunk 是 data: {...},以 data: [DONE] 结束。

curl -sS --no-buffer __BASE_URL__/v1/chat/completions \
  -H "Authorization: Bearer $VKEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "or-claude-haiku",
    "messages": [{"role":"user","content":"hi"}],
    "stream": true
  }'

Responses API

POST /v1/responses OpenAI 新一代 stateful chat API

跟 /v1/chat/completions 不同:用 input 字段而非 messages;响应是 output[] 数组,每项有 type (message / tool_use / refusal...) 和 content[] 块。Codex / GPT-5 系列模型都走这条。

curl -sS __BASE_URL__/v1/responses \
  -H "Authorization: Bearer $VKEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.4",
    "input": "用一句话解释 RAG。"
  }'

input 也可以是消息数组,带 system 指令:

curl -sS __BASE_URL__/v1/responses \
  -H "Authorization: Bearer $VKEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.5",
    "input": [
      {"role": "system", "content": "You are concise."},
      {"role": "user",   "content": "List 3 NoSQL databases."}
    ],
    "max_output_tokens": 200
  }'

响应形如:

{
  "id": "resp_xxxxx",
  "object": "response",
  "model": "gpt-5.5",
  "status": "completed",
  "output": [
    {
      "type": "message",
      "role": "assistant",
      "content": [
        {"type": "output_text", "text": "1. MongoDB\n2. Redis\n3. Cassandra"}
      ]
    }
  ],
  "usage": {"input_tokens": 28, "output_tokens": 18, "total_tokens": 46}
}

流式加 "stream": true,SSE 事件名是 response.created / response.output_text.delta / response.completed:

curl -sS --no-buffer __BASE_URL__/v1/responses \
  -H "Authorization: Bearer $VKEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.4",
    "input": "用三句话讲一个童话。",
    "stream": true
  }'

Anthropic 兼容

POST /v1/messages Anthropic / Claude 原生 schema

Anthropic 官方 schema,可直接用 @anthropic-ai/sdk 或 anthropic Python 包。注意 3 点:

  • system 是 顶层字段,不放在 messages 里
  • max_tokens 是 必填
  • content 可以是字符串,也可以是块数组(混合图文用)
curl -sS __BASE_URL__/v1/messages \
  -H "Authorization: Bearer $VKEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-haiku-4.5",
    "max_tokens": 256,
    "system": "你是一个简明扼要的助手。",
    "messages": [
      {"role": "user", "content": "解释一下 RAG。"}
    ]
  }'

带图片(content 块数组):

curl -sS __BASE_URL__/v1/messages \
  -H "Authorization: Bearer $VKEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4.5",
    "max_tokens": 512,
    "messages": [{
      "role": "user",
      "content": [
        {"type": "text",  "text": "这张图里有什么?"},
        {"type": "image", "source": {
          "type": "base64", "media_type": "image/png", "data": "iVBORw0KGgo..."
        }}
      ]
    }]
  }'

响应形如:

{
  "id": "msg_xxxxx",
  "type": "message",
  "role": "assistant",
  "model": "claude-haiku-4.5",
  "content": [
    {"type": "text", "text": "RAG 即检索增强生成..."}
  ],
  "stop_reason": "end_turn",
  "usage": {"input_tokens": 25, "output_tokens": 88}
}

流式加 "stream": true,事件类型有 message_start / content_block_delta / message_delta / message_stop:

curl -sS --no-buffer __BASE_URL__/v1/messages \
  -H "Authorization: Bearer $VKEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-haiku-4.5",
    "max_tokens": 200,
    "stream": true,
    "messages": [{"role":"user","content":"hi"}]
  }'

图像生成

POST /v1/images/generations OpenAI 图像 API 兼容(JSON) 
curl -sS __BASE_URL__/v1/images/generations \
  -H "Authorization: Bearer $VKEY" -H "Content-Type: application/json" \
  -d '{
    "model":  "gemini-3-pro-image-preview",
    "prompt": "a serene mountain at dawn, watercolor style",
    "n":      1,
    "size":   "1024x1024"
  }'

响应形如(b64_json 或 url,取决于模型):

{
  "created": 1729123456,
  "data": [
    {"b64_json": "iVBORw0KGgo..."}
  ]
}

图像编辑

POST /v1/images/edits multipart form,不是 JSON

跟 generations 不同,这条必须用 multipart/form-data(因为要上传图)。字段:

  • image — 必填,要编辑的原图(PNG / JPG)
  • prompt — 必填,编辑指令
  • mask — 可选,蒙版图(白色区域=要修改的部分);不传则模型按 prompt 自己决定
  • model — 可选,默认走模型路由
  • n — 可选,生成几张
  • size — 可选,如 1024x1024

基础用法(无 mask,整图修改):

curl -sS __BASE_URL__/v1/images/edits \
  -H "Authorization: Bearer $VKEY" \
  -F "image=@./input.png" \
  -F "prompt=convert this photo to oil painting style" \
  -F "model=gemini-3-pro-image-preview" \
  -F "n=1" \
  -F "size=1024x1024"

带 mask(只修改蒙版白色区域):

curl -sS __BASE_URL__/v1/images/edits \
  -H "Authorization: Bearer $VKEY" \
  -F "image=@./photo.png" \
  -F "mask=@./mask.png" \
  -F "prompt=replace the sky with a sunset"

响应跟 generations 一样,data[] 数组里是 b64_json 或 url。

Gemini 原生 API

如果你的客户端是 Google 官方 SDK (@google/generative-ai、google-generativeai),走这套原生协议。请求/响应 schema 与 Google AI Studio 一致。

generateContent (unary)

POST /v1beta/models/{model}:generateContent 模型名在 URL,不在 body

注意 3 点和 OpenAI 不同:

  • 模型名在 URL(:generateContent 前面),body 里没有 model 字段
  • 消息字段是 contents[],每条有 role + parts[];不是 messages[]
  • 参数在 generationConfig(temperature / maxOutputTokens 等)
curl -sS __BASE_URL__/v1beta/models/gemini-2.5-flash:generateContent \
  -H "Authorization: Bearer $VKEY" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {"role": "user", "parts": [{"text": "用一句话解释 RAG。"}]}
    ],
    "generationConfig": {
      "temperature": 0.4,
      "maxOutputTokens": 200
    }
  }'

带 system 指令(放 systemInstruction,不放 contents):

curl -sS __BASE_URL__/v1beta/models/gemini-2.5-pro:generateContent \
  -H "Authorization: Bearer $VKEY" \
  -H "Content-Type: application/json" \
  -d '{
    "systemInstruction": {"parts": [{"text": "你是一位简明扼要的助手。"}]},
    "contents": [
      {"role": "user", "parts": [{"text": "比较一下 RAG 和 fine-tuning。"}]}
    ]
  }'

带图(inline_data base64):

curl -sS __BASE_URL__/v1beta/models/gemini-2.5-flash:generateContent \
  -H "Authorization: Bearer $VKEY" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [{
      "role": "user",
      "parts": [
        {"text": "这张图里有什么?"},
        {"inline_data": {"mime_type": "image/png", "data": "iVBORw0KGgo..."}}
      ]
    }]
  }'

响应:

{
  "candidates": [{
    "content": {
      "parts": [{"text": "RAG (Retrieval-Augmented Generation) ..."}],
      "role": "model"
    },
    "finishReason": "STOP",
    "index": 0
  }],
  "usageMetadata": {
    "promptTokenCount":     8,
    "candidatesTokenCount": 42,
    "totalTokenCount":      50
  },
  "modelVersion": "gemini-2.5-flash"
}

streamGenerateContent (SSE)

POST /v1beta/models/{model}:streamGenerateContent?alt=sse 流式 — 加 ?alt=sse 才走 SSE 格式

不加 ?alt=sse 默认返回 JSON 流(每个 chunk 一行 JSON)。多数客户端希望 SSE,加上 ?alt=sse 才走 data: ... 格式。

curl -sS --no-buffer "__BASE_URL__/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer $VKEY" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [{"role":"user","parts":[{"text":"数到 5"}]}]
  }'

列模型 / 查模型

GET /v1beta/models Gemini 原生命名,已按 vkey 白名单过滤 
curl -sS __BASE_URL__/v1beta/models -H "Authorization: Bearer $VKEY" | jq '.models | length'

查单个模型详情:

curl -sS __BASE_URL__/v1beta/models/gemini-2.5-pro \
  -H "Authorization: Bearer $VKEY"

模型列表

GET /v1/models 仅返回本 vkey 有权调用的

响应是 OpenAI 标准 {"data":[{"id":"...","object":"model"}, ...]}。常见模型节选:

ProviderOAuth(订阅,对你 $0)API key(按 token 计费)
Codex (ChatGPT Plus)gpt-5.4, gpt-5.5, gpt-5.3-codex, codex-*—
Geminigemini-2.5-pro, gemini-2.5-flash, gemini-3-pro-image-preview—
Groq—llama-3.3-70b, qwen3-32b, gpt-oss-20b, gpt-oss-120b
OpenRouter—or-claude-haiku, or-claude-sonnet, or-gpt-4o, or-ds-chat
OAuth 模型走 ChatGPT Plus / Gemini 订阅,对你免费;但订阅有 5h / 7d 配额窗口,触顶会 429,可改 API key 模型继续。

额度查询

GET /v1/balance 本 vkey 的累计 / 今日 / 配额 
{
  "label":                "colleague",
  "owner":                "",
  "total_spent_usd":      0.0,
  "today_spent_usd":      0.0,
  "total_requests":       12,
  "budget_usd":           0,
  "daily_budget_usd":     0,
  "rpm_limit":            0,
  "tpm_limit":            0,
  "budget_remaining_usd": null,
  "daily_remaining_usd":  null
}

所有 *_limit / budget_* 字段:0 表示不限,*_remaining_* 为 null 表示不限。

响应 header

每个成功的调用都会在响应 header 里带上当前的额度状态,无需额外查询。

Header含义
X-RateLimit-Limit-Requests本 vkey 的 RPM 上限(0 = 不限)
X-RateLimit-Remaining-Requests本分钟剩余请求数
X-RateLimit-Limit-Tokens本 vkey 的 TPM 上限
X-RateLimit-Remaining-Tokens本分钟剩余 token 配额
X-Budget-Limit-USD总预算上限(美元)
X-Budget-Remaining-USD总预算剩余
X-Daily-Budget-Limit-USD日预算上限
X-Daily-Budget-Remaining-USD今日剩余日预算
X-Daily-Budget-Reset下一次日预算重置时间(UTC ISO8601)

错误码

HTTP含义
401vkey 缺失 / 错误 / 过期 / 禁用
403这个 vkey 没权限调这个模型
413请求体超过 max_body_kb(默认 2 MB)
429限额触发 —— RPM / TPM / budget / 日预算 / 并发,看 X-*-Remaining
502上游(OpenAI / Anthropic / Gemini)错
504上游超时(可重试)

错误体统一形如:

{"error": {"message": "rate limit exceeded: 60/60 in last 60s", "type": "rate_limit_exceeded"}}

限制

  • 请求体最大 2 MB(可单独放宽,联系管理员调 max_body_kb)
  • 并发数受 vkey 的 max_concurrent 限制(0 = 不限)
  • SSE 流式连接保持时间无硬上限,但建议客户端 60s 无 chunk 就重连

上游配额透传

除了上面列的 X-RateLimit-* / X-Budget-*(都是本 vkey 的状态)之外,上游 OAuth 账号的额度情况:

  • Codex (ChatGPT Plus) — 上游会通过 X-Codex-Primary-Used-Percent / X-Codex-Secondary-Used-Percent 等 header 返回 5h / 7d 配额窗口的实时占用。本网关在服务端跟踪并显示在管理面板,不透传给客户端(客户端只关心自己 vkey 余额,OAuth 账号配额由管理员维护)。
  • Gemini OAuth — Google 不暴露剩余配额。触顶时只能从 429 + quotaResetDelay 得知。这是 Google 的限制,不是本网关漏报。
  • OpenRouter / Groq (API key) — 按 token 实时计费,余量在管理员侧统一管理(/api/openrouter-balance)。

完整 cURL 示例

把下面的 $VKEY 换成自己的 vkey 即可:

export VKEY="vk-你的key"
export BASE="__BASE_URL__"

# 1. 列模型
curl -sS $BASE/v1/models -H "Authorization: Bearer $VKEY" | jq '.data | length'

# 2. 查余额
curl -sS $BASE/v1/balance -H "Authorization: Bearer $VKEY"

# 3. chat (非流式)
curl -sS $BASE/v1/chat/completions \
  -H "Authorization: Bearer $VKEY" -H "Content-Type: application/json" \
  -d '{"model":"llama-3.3-70b","messages":[{"role":"user","content":"hi"}]}'

# 4. chat (流式)
curl -sS --no-buffer $BASE/v1/chat/completions \
  -H "Authorization: Bearer $VKEY" -H "Content-Type: application/json" \
  -d '{"model":"or-claude-haiku","messages":[{"role":"user","content":"hi"}],"stream":true}'
